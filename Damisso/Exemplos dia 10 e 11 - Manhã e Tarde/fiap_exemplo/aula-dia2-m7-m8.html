2 — O que é relação 1:N

1:N = um lado tem vários do outro. Uma Ana, muitos pedidos. Não o contrário.

No C# isso vira uma propriedade de cada lado. O EF usa para juntar as tabelas (JOIN).

Models — ideia
class Contribuinte { public List<PedidoBeneficio> Pedidos { get; set; } } class PedidoBeneficio { public int ContribuinteId { get; set; } public Contribuinte? Contribuinte { get; set; } }

Nomes

ContribuinteId = chave estrangeira (já temos).

Contribuinte = a ficha do outro lado.

Pedidos = a gaveta da Ana.

Sem isto, Include não funciona.

3 — O que é Include

Include = “além da Ana, traga os pedidos dela”. Sem isso o EF devolve a ficha e a lista vem vazia.

GET /api/contribuintes/1/pedidos
var c = await _db.Contribuintes .AsNoTracking() .Include(x => x.Pedidos) .FirstOrDefaultAsync(x => x.Id == id, ct);

Tradução

SQL faz JOIN.

A Ana volta com a lista de pedidos.

Sem Include = Pedidos vazio.

4 — O que é LINQ

LINQ = escrever a pergunta em C#. O EF vira SQL. Vocês não abrem o inss.db à mão.

No GET de pedidos: “abertos, ordenados, só o tipo”.

Consulta
_db.Pedidos
  .Where(x => x.Status == "Aberto")
  .OrderBy(x => x.Id)
  .Select(x => x.Tipo)
MétodoIdeia
WhereFiltrar
OrderByOrdenar
SelectProjetar (escolher campos)

Performance

O filtro acontece no SQLite — não na memória da API.

ToListAsync no fim. Antes é só a receita.

6 — Paginação (porquê)

Paginação = não devolver 1000 pedidos de uma vez. O Swagger pede a fatia: página e tamanho.

Swagger — query
GET /api/pedidos?pagina=1&tamanho=2
QuerySignificado
paginaQual fatia (começa em 1)
tamanhoQuantos por fatia (máx. 50)

SQL

Skip + Take = OFFSET / LIMIT.

Página 1, tamanho 2 → 2 itens. total não muda.

6 — Paginação (código)

Skip + Take + Select

7 — Transação (tudo ou nada)

Transação = ou o pedido da Ana grava inteiro, ou não grava nada. Se o SaveChanges falhar no meio, o arquivo volta atrás.

Ideia no POST do pedido
await using var tx = await _db.Database.BeginTransactionAsync(ct); try { _db.Pedidos.Add(p); await _db.SaveChangesAsync(ct); await tx.CommitAsync(ct); } catch { await tx.RollbackAsync(ct); throw; }

Quando

1 SaveChanges já é uma transação.

BeginTransaction quando há vários passos.

Erro no meio = nada gravado.

4 — O que é injeção de dependência

DI = vocês não fazem new. O ASP.NET entrega o objeto no construtor.

Ontem já era assim: ContribuintesController(AppDbContext db).

Hoje o construtor pede o Service. O Service pede o Repository. O Repository pede o AppDbContext.

Program.cs — a lista de “quem entrega o quê”
builder.Services.AddScoped<IContribuinteRepository, ContribuinteRepository>(); builder.Services.AddScoped<IContribuinteService, ContribuinteService>();

A letra I

IContribuinteService = o contrato.

A classe de verdade vem depois da vírgula.

Sem esta linha: unable to resolve.

5 — Ciclo de vida (quanto tempo vive)

Cada clique no Swagger é um pedido HTTP. O AddScoped cria Service + Repo + DbContext para aquele clique e joga fora no fim.

Tudo que toca inss.db = Scoped.

Singleton + DbContext = disposed.

7 — O que é middleware de erros

Middleware = um portão no caminho de todo request. Este aqui pega exception que ninguém tratou.

O Swagger não vê stack. Vê: “Erro interno” + um número para achar no log.

ErrosMiddleware — ideia
try { await _next(context); } catch (Exception ex) { _logger.LogError(ex, "Falha. TraceId={TraceId}", context.TraceIdentifier); // JSON 500: erro + correlacao }

Onde liga

app.UseMiddleware<...>() no Program.cs.

Um lugar só. Todos os endpoints.

8 — O que é log estruturado

Log = livro de ponto. “Criei a Ana 123456789.” Não é Console.WriteLine.

Estruturado = o NUIT vai num campo {Nuit}, dá para procurar depois.

No Service, depois do SaveChanges
_logger.LogInformation("Contribuinte criado {Nuit}", n);
_logger.LogWarning("NUIT duplicado {Nuit}", n);

Onde ver: Visual Studio → Exibir → Saída.

Vocês fazem

POST a Ana → aparece a linha.

POST de novo → Warning.

O cidadão no Swagger não vê isso.

9 — O que é correlação

Correlação = número do processo daquela visita. Um Execute no Swagger = um id.

Se o aluno diz “deu 500”, vocês procuram esse id no Output e acham só aquele clique — não o do colega do lado.

No ASP.NET o nome é TraceIdentifier. O middleware devolve no JSON 500 como correlacao.

Junto

Log = o que aconteceu.

Correlação = de qual clique.

Observabilidade = ver o posto por dentro.
