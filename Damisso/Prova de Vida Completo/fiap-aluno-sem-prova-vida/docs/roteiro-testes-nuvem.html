Testes + subir na nuvem — passo a passo

Pacote fiap-aluno-sem-prova-vida. Ordem: testes no PC → contas → GitHub → Neon → Render → Vercel → CORS → validar a URL do projeto.

Slides
Antes de começar: a pasta do projeto já está no HD (ex.: C:\fiap-aluno). Têm internet. Browser: Chrome ou Edge.
Minhas URLs — deixem esta página aberta. Quando o GitHub / Render / Vercel mostrar um endereço, copiem e colem no campo abaixo. Nos passos seguintes usam estes mesmos campos (fica salvo neste browser).

Os valores ficam salvos neste browser automaticamente.

Parte A — Testar no PC (xUnit / Moq)

A1
ONDE Windows → digitem PowerShell → Enter
DIGITAM
cd C:\fiap-aluno\projeto\api
APARECE o prompt terminando em ...\projeto\api>
Se a pasta for outra, usem o caminho real. Digitem dir — devem ver a pasta tests.
A2
ONDE mesmo PowerShell
DIGITAM (pode demorar 1–2 min na 1ª vez)
dotnet test --filter "FullyQualifiedName~UnitTests"
APARECE no final algo como:
Passed!  - Failed: 0
Se aparecer “não é reconhecido”: instalem o .NET SDK e abram um PowerShell novo.
A3 — Ver um teste xUnit
ONDE Explorador de Arquivos
ABREM este arquivo (botão direito → Abrir com Bloco de Notas ou VS Code):
C:\fiap-aluno\projeto\api\tests\Contribuintes.UnitTests\Domain\ContribuinteTests.cs
PROCUREM a linha com 1350m — é o Assert do 3% do salário.

Isso é um teste unitário: não precisa de internet nem de API ligada.

A4 — Ver um teste Moq
ABREM
C:\fiap-aluno\projeto\api\tests\Contribuintes.UnitTests\Application\ContribuinteServiceTests.cs
PROCUREM a palavra Mock e Setup.

Moq = “mentira” do banco. O teste finge que o repositório já tem um NUIT.

A5 — Exercício (2 minutos)
  1. No arquivo do A3, mudem 1350m para 999m · salvem
  2. No PowerShell: 
    dotnet test --filter "FullyQualifiedName~ContribuinteTests"
  3. APARECE Failed
  4. Voltem para 1350m · salvem · rodem de novo · verde

Parte B — Criar contas

B0.1 — Conta GitHub
ONDE Chrome
ABREM https://github.com/signup
  1. Digitem e-mail · senha · usuário (ex.: joaoinss)
  2. Resolvam o captcha se pedir
  3. Confirmem o e-mail (abrim a caixa de entrada)
APARECE a página inicial do GitHub logado (avatar no canto superior direito).
Colem o usuário GitHub no campo Usuário GitHub em Minhas URLs (topo desta página).
Já têm GitHub? Pulem para B0.2 — só façam login.
B0.2 — Conta Neon (banco Postgres)
ABREM https://console.neon.tech/signup
  1. Cliquem em Continue with GitHub (botão grande)
  2. Se o GitHub pedir, cliquem Authorize / Autorizar
  3. Esperem abrir o painel do Neon
APARECE dashboard Neon (pode pedir criar projeto — isso será no passo C3).
B0.3 — Conta Render (APIs)
ABREM https://dashboard.render.com/register
  1. Cliquem GitHub / Sign up with GitHub
  2. Authorize Render
  3. Se perguntar plano: escolham Free / Hobby free
APARECE Dashboard do Render (página em branco ou “Create a new service”).
B0.4 — Conta Vercel (portal React)
ABREM https://vercel.com/signup
  1. Cliquem Continue with GitHub
  2. Authorize Vercel
  3. Se perguntar Hobby / Pro → escolham Hobby (grátis)
APARECE dashboard Vercel (“Add New…”).
Agora têm 4 logins. Próximo: enviar o código.

Parte C — Publicar o projeto (clique a clique)

C1 — Criar repositório vazio no GitHub
ONDE Chrome · logados no GitHub
  1. Canto superior direito: botão + → New repository
  2. Repository name: digitem inss-fiap- + o vosso nome (sem espaços), ex.: inss-fiap-joao
  3. Public ou Private — tanto faz
  4. NÃO marquem “Add a README file”
  5. NÃO marquem .gitignore nem license
  6. Cliquem o botão verde Create repository
APARECE uma página com comandos git remote add origin ...
Na barra do browser aparece algo como https://github.com/joaoinss/inss-fiap-joao. Colem o usuário e o nome do repo nos campos de Minhas URLs.
C2 — Enviar a pasta do HD para o GitHub
ONDE PowerShell

Primeiro confiram se o git existe:

git --version
Se “não é reconhecido”: instalem Git (git-scm.com) ou usem o GitHub Desktop: Add Local Repository → Publish repository.
DIGITAM um comando de cada vez (troquem a URL pela do vosso repo):
cd C:\fiap-aluno
git init
git add .
git status
git commit -m "INSS FIAP aluno"
git branch -M main
git remote add origin https://github.com/SEU_USUARIO/inss-fiap-SEU_NOME.git
git push -u origin main

Na primeira vez o GitHub pode abrir o browser para autorizar / pedir login.

APARECE no final branch 'main' set up to track...
CONFEREM no browser: atualizem a página do repo → veem pastas projeto e docs.
Erro “remote origin already exists”: 
git remote remove origin
git remote add origin https://github.com/SEU_USUARIO/inss-fiap-SEU_NOME.git
git push -u origin main
C3 — Neon: criar projeto e 2º banco
ONDE console.neon.tech
  1. Se pedirem projeto: Create project · nome inss-aula · região perto (ex. Frankfurt ou US) · Create
  2. Na tela do projeto, procurem Connection string ou Connect
  3. Copiem a string que parece postgresql://usuario:senha@host/neondb?... · colem no Bloco de Notas
  4. Abram o menu SQL Editor
  5. Digitem exatamente e rodem (Run / Play):
CREATE DATABASE inss_beneficios;
APARECE sucesso / “CREATE DATABASE”

Agora montem 2 strings no Bloco de Notas (mesmo host/usuário/senha; só muda Database):

Do connection string original, tirem Host, User, Password. Formato para o Render:

Host=SEU_HOST.neon.tech;Database=neondb;Username=SEU_USER;Password=SUA_SENHA;SSL Mode=Require;Trust Server Certificate=true

Host=SEU_HOST.neon.tech;Database=inss_beneficios;Username=SEU_USER;Password=SUA_SENHA;SSL Mode=Require;Trust Server Certificate=true
Se o DB padrão não for neondb, usem o nome que o Neon mostrou na connection string.
String 1 = Contribuintes · String 2 = Benefícios.

C6 — Vercel: publicar o portal
ONDE vercel.com/dashboard
  1. Add New… → Project
  2. Importem o repo inss-fiap-... (botão Import)
  3. Antes de Deploy, cliquem em Root Directory → Edit → digitem projeto/app → Continue
  4. Framework deve aparecer Vite (se não, escolham Vite)
  5. Abram Environment Variables e adicionem duas:
KeyValue (copiar de Minhas URLs)
VITE_CONTRIBUINTES_APIcampo URL API Contribuintes (sem / no fim)
VITE_BENEFICIOS_APIcampo URL API Benefícios (sem / no fim)
  1. Cliquem Deploy
  2. Esperem o build terminar (1–3 min)
APARECE “Congratulations” + botão Visit
Colem a URL https://….vercel.app no campo URL do portal (Vercel) em Minhas URLs.
C7 — CORS (senão o login falha)
ONDE Render → abram o serviço Contribuintes
  1. Menu esquerdo: Environment
  2. Add Environment Variable:
Key:   Cors__Origins
Value: https://SEU-PROJETO.vercel.app

(cole a URL Vercel de Minhas URLs · sem barra no final)

  1. Save · esperem redeploy
  2. Repitam igual no serviço Benefícios
Se esquecerem o CORS: no portal aparece erro de rede / Failed to fetch.
C8 — Testar a URL de VOCÊS
  1. Abram no Chrome a URL Contribuintes do Render · esperem carregar (pode demorar 1 min — Free dorme)
  2. Abram a URL Benefícios do Render · esperem
  3. Abram a URL Vercel de vocês
  4. Login: usuário admin · senha 123
  5. Devem ver a lista de contribuintes
  6. Cliquem em um nome · depois criem um contribuinte novo (NUIT com 9 dígitos)
  7. Vão em pedidos / benefícios · criem um pedido
SUCESSO se lista + criar funcionarem na sua URL Vercel.
Portal vazio? Esperem as APIs acordarem · F5 · confira CORS e se as VITE_* estão certas (se mudarem env na Vercel, façam Redeploy).
