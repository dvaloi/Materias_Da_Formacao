Parte 3 — Práticas M13

Arquivos: VS Code → projeto\app → busquem M13 (Ctrl+Shift+F).

P1 — Formulário controlado + validação

Arquivo: ContribuinteForm.jsx

CT-01 — NUIT inválido

Façam: abrir formulário de novo contribuinte · digitar NUIT com menos de 9 dígitos (ex.: 123) · tentar salvar.

Esperado: mensagem “NUIT deve ter exatamente 9 dígitos” · não grava.

CT-02 — Nome curto

Façam: nome com 1–2 letras · NUIT de 9 dígitos · salvar.

Esperado: erro de nome (mínimo 3 caracteres).

CT-03 — Salário inválido

Façam: salário 0 ou negativo · salvar.

Esperado: mensagem de salário maior que zero.

CT-04 — Cadastro válido

Façam: NUIT 9 dígitos (ex.: 987654321) · nome completo · data · salário > 0 · salvar.

Esperado: sucesso · aparece na lista · contribuição ≈ 3% do salário (MZN).

P2 — React Router + parâmetro :id

Arquivos: App.jsx · ContribuinteDetail.jsx

CT-05 — Navegação lista → detalhe

Façam: na lista, abrir Detalhes de um contribuinte.

Esperado: URL muda para algo como /contribuintes/…id… · dados do contribuinte na tela.

CT-06 — Voltar pela rota

Façam: voltar para a lista (link/menu) · URL volta para /contribuintes.

Esperado: lista de novo · página não recarregou o site inteiro (SPA).

P3 — Estados da interface

Arquivos: ContribuintesList.jsx · PedidosList.jsx · LoadingSpinner · ErrorMessage

CT-07 — Sucesso (lista com dados)

Façam: abrir Contribuintes com a API no ar.

Esperado: lista com seed (ou o que vocês cadastraram).

CT-08 — Vazio (não é erro)

Façam: abrir Pedidos (pode estar vazio na 1ª vez).

Esperado: estado vazio / mensagem amigável · status HTTP 200 (lista []).

CT-09 — Erro (API desligada)

Façam: parar a API Contribuintes (Ctrl+C no terminal :5001) · F5 na lista.

Esperado: estado de erro na UI (não tela branca). Depois subam a API de novo.

P4 — Integração HTTP + Network

Arquivos: api.js · main.jsx (Strict Mode)

CT-10 — Ver a chamada no Network

Façam: F12 → Network → filtro Fetch/XHR → abrir Pedidos.

Esperado: request para a API de benefícios (:5002) · status 200 (mesmo se lista vazia).

CT-11 — Strict Mode (2× em dev)

Façam: contar quantas vezes a mesma URL aparece ao abrir a tela.

Esperado: em desenvolvimento pode aparecer 2 vezes · não é bug · em produção seria 1×.

Parte 4 — Práticas M14

Arquivos: busquem M14 · Login.jsx · AuthContext.jsx · ProtectedRoute.jsx

P5 — Autenticação JWT

CT-12 — Login inválido

Façam: usuário/senha errados · entrar.

Esperado: mensagem de erro · sem token · não entra no portal.

CT-13 — Login válido + token

Façam: admin / 123 · DevTools → Application → Local Storage → achar inss_token.

Esperado: token JWT gravado · entra nas telas internas.

CT-14 — Bearer no Network

Façam: com login feito · F12 Network → abrir uma lista · inspecionar request.

Esperado: header Authorization: Bearer …

P6 — Rotas protegidas + sessão

CT-15 — Sem token → login

Façam: apagar inss_token no Local Storage · F5 · tentar abrir /contribuintes.

Esperado: redireciona para /login.

CT-16 — Logout / 401

Façam: (se houver botão sair) logout · ou corromper o token e chamar a API.

Esperado: sessão limpa · volta ao login.

P7 — Qualidade de UI

CT-17 — Responsivo

Façam: estreitar a janela do browser (mobile).

Esperado: layout usável · sem “quebrar” o formulário.

CT-18 — Teclado / foco

Façam: no formulário, navegar só com Tab.

Esperado: foco visível nos campos · ordem faz sentido.

P8 — 2º microsserviço (pedidos / Benefícios)

Arquivos: PedidoForm.jsx · PedidosList.jsx · API :5002

CT-19 — Criar pedido

Façam: no detalhe de um contribuinte → novo pedido · tipo (ex.: reforma/pensão) · valor em MZN (pode usar vírgula) · salvar.

Esperado: pedido criado · aparece na lista de pedidos · Network mostra POST na API :5002 (não na :5001).

CT-20 — Pedido com API Benefícios off

Façam: desligar :5002 · tentar listar/criar pedido.

Esperado: erro na UI de pedidos · contribuintes (:5001) ainda pode funcionar (microsserviços independentes).
