O que é um GUID?

Identificador único — a “chave” da pessoa entre os dois mundos.

e5f6a7b8-1111-2222-3333-444455556666
  • Em Contribuintes → coluna Id
  • Em PedidosBeneficio → coluna ContribuinteId
  • Mesmo valor = mesma pessoa · sem copiar Nome/NUIT

Mesmo GUID nos dois bancos

Banco 1 · Contribuintes

IdNuitNome
e5f6…6666100200301Ana Celeste

Banco 2 · Pedidos

Id pedidoContribuinteIdTipo
a1b2…9999e5f6…6666Reforma
ContribuinteId = Id → a ponte

Isto NÃO é “falta”

É a arquitetura — 2 bounded contexts.

  • ❌ Um único banco com as duas tabelas
  • ❌ JOIN SQL entre os dois databases
  • ❌ Coluna Nome em PedidosBeneficio
  • ❌ As duas APIs se chamando para gravar o pedido

Por que sem JOIN · vale a pena

  • Independência
    :5001 ok com :5002 parado
  • Clareza
    Cadastro num lugar · pedido noutro
  • Menos acoplamento
    Cada API dona do seu dado
  • Deploy
    Publicar um contexto sem derrubar o outro
Ponte = ContribuinteId (GUID) · 2 contextos / 2 bancos
